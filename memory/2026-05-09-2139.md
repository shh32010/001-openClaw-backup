assistant: ## `openclaw-task.xml` — Windows 计划任务

这是 `openclaw gateway install` 自动生成的 **Windows 计划任务**，作用是让 Gateway **开机自启 + 崩溃自愈**。

### 触发条件（Triggers）

| 触发器 | 含义 |
|---|---|
| `BootTrigger` | **开机时**自动启动 Gateway |
| `LogonTrigger` | **用户登录时**启动（比 Boot 更晚，确保网络就绪） |
| `TimeTrigger` 每 5 分钟 | **定时巡检**，如果 Gateway 挂了就拉起来 |

### 重启策略（RestartOnFailure）

```xml
<RestartOnFailure>
  <Count>3</Count>        <!-- 最多重试 3 次 -->
  <Interval>PT5M</Interval> <!-- 每次间隔 5 分钟 -->
</RestartOnFailure>
```

### 其他设置

| 配置 | 值 | 含义 |
|---|---|---|
| `DisallowStartIfOnBatteries` | false | 笔记本用电池时也能启动 |
| `StopIfGoingOnBatteries` | false | 切到电池不会停 |
| `MultipleInstancesPolicy` | IgnoreNew | 已经在跑就不重复启动 |
| `ExecutionTimeLimit` | PT0S | 无时间限制，永远运行 |
| `AllowHardTerminate` | true | 允许强制终止 |

### 执行内容

```xml
<Command>C:\Users\001\.openclaw\gateway.cmd</Command>
```

就是跑你的 Gateway 启动脚本。

---

## `params.json` — 启动参数

```json
{
  "ipc": true,
  "pid": null
}
```

| 字段 | 含义 |
|---|---|
| `ipc: true` | 启用 IPC（进程间通信），让 CLI 工具（如 `openclaw status`）能和运行中的 Gateway 进程对话 |
| `pid: null` | 当前没有记录 PID（启动后会写入实际 PID） |

---

简单来说：**xml 是"怎么保活"，params 是"怎么通信"。** 一个负责 Gateway 挂了自动拉起来，一个负责 CLI 和 Gateway 之间能互相找到对方。
